# 音乐外屏增强 · MusicEnhance

为 **Xiaomi MIX Flip / MIX Flip 2** 打造的外屏音乐播放器增强模块，基于 **libxposed API 102**。

在外屏使用 QQ 音乐时，提供全屏专辑背景、低频律动、滚动歌词和围绕摄像头布局的播放控件。设置界面采用 Miuix 风格。

[下载安装](https://github.com/daixu0502/MusicEnhance/releases) · [反馈问题](https://github.com/daixu0502/MusicEnhance/issues) · [构建与发布](#本地构建) · [开发与扩展](#开发与扩展)

## 支持范围

| 项目 | 当前适配 |
| --- | --- |
| 设备 | Xiaomi MIX Flip（`ruyi`）、Xiaomi MIX Flip 2（`bixi`） |
| 系统 | 小米 HyperOS，安装最低要求为 Android 14（API 34） |
| 框架 | 支持现代 **libxposed API 102** 的 LSPosed 环境 |
| 音乐应用 | QQ 音乐 20.8.5.8、Apple Music 6.5.2、酷狗概念版 5.2.9、酷我音乐 12.2.2.4、酷狗音乐普通版 20.8.2、椒盐音乐 12.3.2 |
| 使用场景 | 外屏播放页；内屏保留音乐应用原界面 |

## 功能

### 外屏播放器

- **页面显示**：在页面创建、恢复及窗口首帧时检查增强界面，保持其位于原生内容之上；控件在首次测量时完成布局，页面退出时取消未执行的加载。
- **窗口全屏**：增强播放器同时申请系统侧全屏布局和应用窗口的摄像头区域绘制权限，避免窗口已全屏但内容仍被裁成左半屏。独立播放页与内嵌播放页共用该策略，离开增强界面后恢复宿主原有设置。
- **全屏封面**：专辑图铺满背景，从屏幕中部向歌曲信息区域逐渐增强模糊；播放器从后台重新显示时会重建 GPU 模糊层，无需等待切歌恢复。
- **摄像头避让**：黑色摄像头区域与控件根据外屏方向布局；正反切换使用整页 180° 旋转动画。
- **低频律动**：以低音、鼓点等低频信号驱动摄像头之间的频谱，颜色取自封面主色；暂停后平滑回落。
- **外屏常亮**：设置页提供「播放器外屏常亮」开关，默认关闭。开启后仅在外屏播放器处于前台时防止自动息屏锁屏，歌词页同样有效；退出、切回内屏或窗口失去焦点后释放，仍可手动锁屏。
- **播放控制**：播放/暂停、上一首、下一首、拖动进度，以及当前歌曲的喜欢状态。
- **直接切换循环模式**：顺序播放 → 列表循环 → 单曲循环 → 随机播放，无需弹出菜单。
- **返回首页**：左上角返回键、预测性返回回调和旧版返回事件共用关闭流程，先关闭原生播放器再退出增强页；兼容未启用新版返回回调的宿主应用。退出后恢复音乐应用首页的原生半屏布局和外屏小部件。

### 滚动歌词

点击播放器中不属于按钮、进度条等控件的空白区域，即可切换到歌词页。

- 专辑背景切换为更深的整屏模糊，歌曲信息移到返回键旁边。
- 黑色侧栏平滑延伸，容纳喜欢、播放/暂停和专辑缩略图。
- 歌词自动跟随播放，通常将上一句、当前句放在前两行；可见歌词逐行错峰上移，带轻微弹簧回弹，快速跳转时从当前位置接续动画。触摸立即停止自动推进，手动滚动不被动画抢占。
- 弹动与模糊在同一绘制帧合并更新，文字层预留模糊空间，保留原有行距和文字点击范围。
- 当前句保持清晰，距离当前句越远，上下两侧的歌词模糊越深。
- 歌词默认以半透明灰色显示，播放到当前句时整句柔和渐变为白色；切换下一句后，上一句渐变回灰色。手动浏览不会把尚未播放的选中句误高亮为白色。
- 手动滚动时平滑取消模糊，并显示中央选中句的开始时间；停止操作约 4 秒后恢复跟随。
- 点击歌词文字可跳转到该句并播放；点击空白区域或专辑缩略图返回封面页。
- QQ 音乐的歌词点击直接调用原生歌词页使用的定位与恢复播放接口，按顺序在后台执行；恢复播放不依赖媒体会话中可能延迟的播放状态。刚启动或已停止时，先启动原生播放器，再按原生歌词页的 500 毫秒准备间隔执行定位。切歌、快速连点或退出后丢弃旧请求。已在 MIX Flip 2、QQ 音乐 20.8.5.8 上验证普通暂停后恢复、播放中跳转及冷启动后点击歌词起播。
- 酷狗概念版的歌词跳转使用原生播放服务，播放中跳转不会额外切换播放/暂停；暂停时跳转会明确开始播放。这两种情况已在 MIX Flip 2、酷狗概念版 5.2.9 上实测。定位失败不继续播放，快速连点、切歌或退出后丢弃尚未执行的旧请求。
- 酷我音乐 12.2.2.4 的歌词点击按原生歌词页的顺序调用定位和继续播放接口，读取原生状态决定是否恢复播放；快速连点只处理最新目标，切歌或退出后取消旧请求。已在 MIX Flip 2 上验证暂停后点击歌词定位并恢复播放，以及播放中点击歌词跳转时保持播放。
- 没有可用逐句歌词时显示空态，不生成示例歌词。

酷狗概念版优先复用原生逐句歌词缓存；未缓存或缓存没有逐句时间轴时，在后台调用该应用的歌词下载与解析接口，不要求先打开原生歌词页。最多尝试前三个歌词候选，避免第一个候选无时间轴就停止。歌词读取当前播放歌曲，按下载请求中的歌曲标识匹配，切歌后丢弃旧结果；确实无歌词时保留空态。

### 封面加载与预缓存

**酷狗音乐普通版 20.8.2**（`com.kugou.android`）与概念版分别注册、分别设置开关，不共用私有方法映射。普通版从原生外屏播放入口进入独立增强 Activity，使用公共全屏与小组件策略，返回时关闭原生数据页面。歌词在后台复用原生缓存和 KRC/LRC 下载解析；无逐句时间轴时继续尝试最多三个候选，不要求先打开原生歌词页。点击歌词使用明确的定位和开始播放操作，避免把播放误切换为暂停。

普通版封面读取当前歌曲原生图片地址，按 **0 原图→1080→720→480→原地址** 兜底；缺失或失效地址再通过原生封面服务查询。不会把原生已经模糊的背景当作清晰封面。当前图和预缓存分开执行，按普通列表前后各三首预取，列表循环跨首尾，随机模式不预测尚未确定的播放顺序；歌曲身份和队列在读取前后校验，取消请求不能覆盖新歌曲。缓存保存于普通版自身目录，容量沿用公共限制。原图清晰度取决于歌曲实际来源。

普通版循环按钮直接轮换列表循环、单曲循环和随机播放；喜欢状态查询原生收藏库，操作保留原生登录与收藏限制，查询失败显示未知。已在 MIX Flip 2、酷狗音乐 20.8.2 上验证首次全屏、返回首页恢复小组件、逐句歌词、暂停后点击歌词恢复播放、三种循环模式、收藏/取消及重新进入后的收藏状态。样例封面读取到 2048×2048，前后六首预取日志均成功；实测切下一首已显示对应封面。其他应用版本、MIX Flip 一代和完整内外屏旋转路径仍需验证。

酷狗概念版读取原生当前歌曲的图片地址，在支持尺寸参数的酷狗图片地址上按 **0 原图→1080→720→480→原地址** 尝试。已对 APK 内两张样例地址实测，原图分别返回 **2700×2700、1614×1417**；指定更大尺寸可能只是服务端放大，因此优先原图。实际清晰度仍取决于歌曲图片来源，原图解码受共享内存限制。低清封面可立即显示，后台高清图通过歌曲标识校验后替换，下载失败不清空已有封面。复用共享内存、磁盘缓存，并按当前播放列表预取前后各三首；只读取附近队列条目，读取前后校验歌曲、队列位置与大小。

酷狗概念版的喜欢状态由后台调用原生收藏缓存/数据库查询，按歌曲哈希与混音编号核对；点击交给原生 `SongFavDelegate`，不再依赖原生页面的按钮标签。原生页面暂停或切换样式后仍可查询普通歌曲的收藏状态。切歌时丢弃旧请求，连续点击在确认期间不重复提交；图标只跟随实际查询结果变化，退出时取消查询与未发出的操作。AI 歌曲使用另一套在线收藏库，目前保持未知/不可用，避免误用普通歌曲的收藏状态。接口已核对 5.2.9 APK，设备上的收藏/取消收藏仍需验证。

QQ 音乐切歌后保留原有封面过渡策略：等待经过歌曲身份校验的封面，等待最多约 1.5 秒后使用已有媒体会话/原生封面。大图不可用时尝试较小尺寸，专辑图不可用时再尝试歌手图，并跳过已识别的 QQ 通用占位封面；后台结果仍校验当前歌曲和请求代次，避免快速切歌后旧请求覆盖新歌。

酷我优先使用封面查询接口的 **size=0 原图**，已测三首样例分别返回 1500×1500、3000×3000、1400×1400；缺图、超出下载大小限制或下载失败时依次尝试 **1080 请求（服务端可能返回 700）→360→歌曲自带图片地址**。前后各三首预缓存使用相同策略，原图解码会按现有内存限制采样。新歌的媒体会话/原生封面可用后立即显示，高清图在后台完成后替换；不用模糊背景图充当封面。旧图片 CDN 地址会转换到证书有效的官方 HTTPS 图片域名，保留原图路径。没有有效歌曲编号的本地文件使用原生封面。

首次进入播放器及切换歌曲后，QQ 音乐、酷我和酷狗概念版会根据**当前播放队列，预缓存前 3 首和后 3 首**的封面：

- 从最近的上一首、下一首开始加载，切歌后更新缓存范围。
- 重叠歌曲复用已有缓存，短列表自动去重；列表循环可跨越首尾。QQ 使用已生成的随机队列；酷我优先读取并校验当前随机顺序，无法读取时缓存普通列表邻居，重新随机生成的歌曲不能提前保证命中。
- 酷狗概念版在随机播放时缓存当前歌曲的普通列表邻居，未预测宿主随机顺序；只有列表循环模式跨越首尾。
- 当前歌曲与预加载使用独立后台任务；切歌或退出后取消过期任务。
- 文件缓存最多 **64 MiB**，图片内存缓存最多 **24 MiB**，不长期保留 6 张解码大图。
- 切歌时背景最多保留上一帧约 1.5 秒。酷我的原生新图到达后立即替换，QQ 保留等待歌曲身份校验的策略；高清图片在后台加载。

封面预加载会使用网络。文件保存在 **对应音乐应用的缓存目录**；被系统或用户清理后，会在后续使用时重新加载。歌曲缺图、网络速度或连续快速切歌仍可能造成等待。

### 椒盐音乐（本地音乐）

椒盐音乐 12.3.2（`com.salt.music`）拥有独立开关与作用域。在外屏展开原生播放器时进入独立增强 Activity，返回音乐库时收起原生播放页；全屏和小组件显隐复用公共窗口策略。

- 歌词直接读取椒盐已经解析的本地逐句歌词，校验所属歌曲 ID；支持本地 CUE 时间偏移。没有逐句时间轴时显示空态，不在线搜索歌词。
- 封面直接读取椒盐的原始封面缓存，不读取已模糊背景，也不另行下载、扫描音乐文件或重复预缓存。解码和缓存继续由椒盐管理，无封面时不把椒盐默认图当作专辑图。
- 循环按钮在列表循环、单曲循环、随机播放间切换。暂停时点击歌词会定位并明确开始播放；快速点击、切歌及退出会作废旧操作。
- 按本项目约定，椒盐的喜欢图标**固定显示为已喜欢**，仅作为显示状态；点击不修改椒盐实际收藏，其他音乐应用仍读取真实收藏状态。

已在 MIX Flip 2、椒盐音乐 12.3.2 上验证首次全屏、返回音乐库恢复小组件、103 行本地歌词、暂停点击歌词恢复播放、三种循环模式与切歌封面。样例原生封面分别为 2000×2000 和 800×800；无封面、无歌词的文件保持空态。MIX Flip 一代、CUE 文件和完整内外屏旋转路径尚未实测。

## 安装与启用

1. 从 [Releases](https://github.com/daixu0502/MusicEnhance/releases) 下载并安装 APK；希望尝试测试版本时，可选择标记为 **Pre-release** 的版本。
2. 在 LSPosed 中启用「音乐外屏增强」，确认以下作用域：

   | 作用域 | 用途 |
   | --- | --- |
   | 系统框架（`system`） | HyperOS 外屏兼容与布局策略 |
   | QQ 音乐（`com.tencent.qqmusic`） | 播放器、歌词、封面和播放控制 |
   | 系统界面（`com.android.systemui`） | 正反方向的系统旋转动画 |
   | Apple Music（`com.apple.android.music`） | 实验性音频播放页与控制 |
   | 酷狗概念版（`com.kugou.android.lite`） | 实验性播放页与控制 |
   | 酷狗音乐（`com.kugou.android`） | 普通版 20.8.2 实验性播放页、歌词、高清封面和预缓存 |
   | 椒盐音乐（`com.salt.music`） | 12.3.2 本地歌词、原生封面缓存和播放控制 |
   | 酷我音乐（`cn.kuwo.player`） | 实验性外屏播放页与控制 |

3. 打开模块设置，确认激活状态；进入「音乐应用 Hook」二级页，分别打开需要使用的音乐应用开关，并按需开启「播放器外屏常亮」。
4. **首次启用或更新模块后，重启手机。**
5. 从外屏打开 QQ 音乐，进入播放页使用增强界面。

各播放器共用独立 Activity 的窗口标记与系统策略：增强窗口出现时应用全屏及隐藏小组件策略，关闭或进程被回收时释放；小米原生前台页面通知与系统观察器刷新负责恢复首页小组件。应用私有适配层只负责识别播放入口和退出原生播放页，无需各写一套小组件逻辑。模块采用静态作用域，新增应用需先安装新版模块，不能在旧包中手动添加；更新后重启手机加载系统侧的新应用名单。各应用的进入、返回、内外屏切换及小组件恢复需结合实际系统版本验证。

Apple Music 与其他应用一样使用独立增强 Activity。**无需勾选外屏桌面作用域**；启用系统框架作用域并重启后，由共用窗口策略处理全屏和小组件显隐。首次进入全屏、小组件恢复和歌词下载仍需结合实际 HyperOS 版本验证。

仅切换模块内的 Hook 开关时，强制停止并重新打开对应音乐应用即可。模块设置页用于配置，不提供独立播放器或预览入口。

## 常见问题

### 启用后界面没有变化

检查设备、QQ 音乐版本和 API 102 框架是否符合上述要求，确认模块作用域和 Hook 开关已启用。首次安装后需重启手机，并在**外屏播放页**查看；内屏和 QQ 音乐首页不会显示增强播放器。

### 为什么有些歌曲显示歌手图，或封面仍需等待？

部分歌曲没有有效专辑图，QQ 会使用歌手图兜底，酷我会尝试较小尺寸及原生图片。预缓存仅覆盖当前队列前后各 3 首，无法覆盖尚未生成的队列、远距离跳转或未完成下载的图片。

### 为什么喜欢按钮暂时不可用？

模块需要先读取 QQ 音乐当前歌曲的收藏状态；数据尚未就绪时会等待，避免把未知状态误显示成「未喜欢」。收藏操作仍由 QQ 音乐处理。

### 安装时提示签名不一致

新旧 APK 需要使用相同证书才能覆盖安装。自行编译的 Debug 包通常与 Release 包签名不同；更换签名前请记录模块设置，必要时卸载旧模块，再安装并重新启用。

### 如何反馈问题？

请在 [Issues](https://github.com/daixu0502/MusicEnhance/issues) 提供设备型号、Android/HyperOS 版本、QQ 音乐版本、模块版本，以及复现步骤。摄像头错位问题请注明进入播放器前后的屏幕方向、是否经历内外屏切换，并附截图或录像。

可同时附上复现后的 LSPosed 日志，模块日志标签为 `MusicEnhance`。封面或歌词问题请补充歌曲名、歌手及具体版本（例如现场版）。分享日志前请检查其中是否包含个人信息。

## 本地构建

需要 **JDK 17** 和 **Android SDK Platform 37.0**（SDK 包名 `platforms;android-37.0`）。使用项目自带的 Gradle Wrapper，无需另外安装 Gradle；首次构建需要联网下载依赖。

将项目导入 Android Studio 并配置 SDK 路径，或通过本地 `local.properties` 设置 `sdk.dir`。当前构建配置可查看 [app/build.gradle.kts](app/build.gradle.kts) 和 [版本目录](gradle/libs.versions.toml)。

以下命令在项目根目录运行，以 Windows PowerShell 为例：

```powershell
# 编译 Debug
.\gradlew.bat :app:assembleDebug

# 单元测试与 Release 静态检查
.\gradlew.bat --no-configuration-cache :app:testDebugUnitTest :app:lintRelease
```

macOS / Linux 使用 `./gradlew` 替换 `.\gradlew.bat`。

## 开发与扩展

新增代码与重构遵循 [项目开发约定](AGENTS.md)，统一结构、命名、播放器适配边界及生命周期管理要求。

播放器界面只依赖 `PlayerController`，订阅统一的 `PlayerDisplayState`：歌曲信息、进度、最终背景图与缩略图、歌词和按钮状态。界面负责展示、模糊、动画与用户交互；点击通过控制器转发至各应用的 lambda 回调。频谱按绘制帧读取已计算的低音样本，不在视图中读取原生音频或进行频谱分析。

`EnhancedPlayerController` 负责数据更新、歌曲匹配和显示状态组装，`PlayerArtworkResolver` 负责封面来源选择、同曲封面保留与切歌背景的限时保留。界面不再轮询歌曲/封面/歌词/控制状态，也不选择封面来源；隐藏时停止数据轮询和监听，退出时释放所有提供器。定位操作校验发起时的歌曲标识，避免拖动中切歌后误定位新歌。

各应用通过 `MusicPlayerAdapter.createSession()` 创建自己的 `PlayerSession`：

| 接口 | 提供内容 |
| --- | --- |
| `PlayerDataSource` | 歌曲快照、状态监听、控制状态、原生封面和频谱数据 |
| `LyricsProvider` | 当前歌曲歌词及加载状态 |
| `ArtworkProvider` | 经过歌曲校验的高清封面、缓存及预取 |
| `PlayerActions` | 播放暂停、上下首、定位、循环和喜欢等 lambda 回调 |
| `PlayerSession.onRelease` | 应用私有监听、任务和资源清理 |

封面下载、内存/磁盘缓存和队列预取由适配器创建的提供器承载：QQ 使用 `QQArtworkProvider`，酷我、酷狗概念版与 Apple Music 各自创建 `PlaylistArtworkProvider` 并注入私有封面来源。四者复用缓存工具代码，各自使用宿主应用的进程内缓存和文件目录，不跨应用共享封面数据。Apple Music 在播放会话所属线程复制当前歌曲和最多六个邻近条目的不可变快照，后台提供器只处理这些快照，下载和图片解码不在主线程运行。

应用私有实现集中在 `adapter/qq`、`adapter/apple`、`adapter/kugoulite`、`adapter/kuwo`。统一入口命名为 `<应用>PlayerAdapter`、`<应用>PlayerProfile`；页面钩子使用 `PlayerHooks`，控制状态使用 `ControlSource`，封面队列使用 `ArtworkSource`，地址处理使用 `ArtworkAddresses`，反射协议使用 `Api`。不同职责不强行使用同名类，也不在通用界面中增加按应用分支。

媒体会话的私有动作含义通过 `MediaSessionControlReader` 注入，状态随跨进程快照传递。`NativeRepeatControl` 负责后台串行读取、合并快速点击和退出取消。`PlayerActivityRouter` 统一管理触发、启动去重、弱引用数据页和启动失败清理；`EnhancedPlayerActivity` 管理界面、方向、返回和资源释放。进程丢失后不尝试复活旧原生对象，缺少会话时直接退出增强页。

后续接入其他播放器，需要补充应用识别、原生控制和数据接口，并进行对应版本的真机验证；添加包名或作用域本身不会完成适配。

| 源码位置 | 职责 |
| --- | --- |
| [adapter](app/src/main/java/com/jaco/musicenhance/adapter) | 应用识别、适配器注册、会话组装和原生接口适配 |
| [player](app/src/main/java/com/jaco/musicenhance/player) | 通用独立 Activity、数据接口、操作回调及控制器 |
| [player/artwork](app/src/main/java/com/jaco/musicenhance/player/artwork) | 封面提供器、下载缓存、队列窗口和背景过渡 |
| [player/lyrics](app/src/main/java/com/jaco/musicenhance/player/lyrics) | 歌词提供器和交互状态 |
| [player/ui](app/src/main/java/com/jaco/musicenhance/player/ui) | 外屏布局、歌词视图和播放控件 |
| [device](app/src/main/java/com/jaco/musicenhance/device) | 外屏检测、摄像头定位与设备布局 |
| [hook](app/src/main/java/com/jaco/musicenhance/hook) | 模块入口及系统、宿主应用钩子 |

接入新播放器时，需要实现 `MusicPlayerAdapter` 和应用 Profile，注册会话工厂，补充原生数据接口，同时更新模块作用域和应用查询配置。缺少的可选能力应返回未知或不支持状态，不要套用 QQ 的私有接口。通用 Activity 不直接引用任何应用适配器。
